0はじめに：何を学ぶの？

この手法の元ネタは @Nyxera0x 氏の投稿とGitHubリポジトリ Nyxera0x/cutaway です。ここでは初心者でも再現できるよう整理しました。

ゴールは次のような成果物を作ること。

  • ロボットのサメなどの精密な機械生物の3D静止画
  • 部品ごとにボタンで分解できるインタラクティブなWebページ
  • 分解→爆発→再組み立てを見せる約21秒の動画と、SNS用の10秒版
この手法の核心 AIに「いい感じに作って」とプロンプトを投げるのではなく、ジョブディスクリプション（仕事の説明書）と画像専用チェックリストを渡して、新人に仕事を任せるように指示する。

学べること

  1. AIに安定して高品質な成果を出させる「指示の設計」
  2. 失敗を数値で記録して次に活かす仕組み
  3. 人間の承認ポイントを入れた制作フロー

📖まず用語を知ろう

用語かんたんな説明
Claude Codeターミナルで動くAIコーディングアシスタント。ファイルを作ったりコードを実行したりできる。
Three.jsブラウザで3Dを表示するJavaScriptライブラリ。画像やモデルファイルを使わずコードだけで形を作れる。
ジョブディスクリプション全ての制作で共通して守らせるルール集（JOB_DESCRIPTION.md）。
チェックリストその画像専用の合格条件。10〜12項目の番号付きリスト。
Still（静止画）参考画像と同じポーズで描画した1枚絵。動画の前に必ず承認を取る。
Film（動画）部品が分解していく映像。静止画承認後に作る。
luma（輝度）ピクセルの明るさ。0が黒、255が白。暗部の量を測るのに使う。
LUFS音量の単位。動画配信では −14 LUFS が目安。
Markdown（.md）とは？ 見出しや箇条書きを簡単な記号で書けるテキスト形式。AIに読ませる指示書によく使われます。

◎ おすすめ✕ 避ける
関節が多い／内部に機械が密集している
（サメ、ピラニア、カニ、昆虫など）		表面がつるっとしたもの

2ジョブディスクリプションを用意する

プロジェクトのフォルダに JOB_DESCRIPTION.md を置き、Claudeに毎回読ませます。

主なルール

  • 白いシェル ＋ クリアコート（つやのある透明コーティング）
  • 緑はアクセントだけ（先端・縁・関節リング）
  • 暗い機械構造を2層で見せる（大きなギア ＋ 約260個の小部品）
  • 作る前に比率を数値で測定してから構築する
  • 静止画を承認するまで動画は作らない

サンプルのイメージ：

# JOB_DESCRIPTION.md（例）
## 役割
あなたは Three.js で精密な機械生物を作る3Dアーティスト兼エンジニアです。

## 見た目のルール
- シェルは白、光沢はクリアコート
- 緑は先端・縁・関節リングのみ
- 暗い機械は2層（大ギア + 小部品およそ260個）

## 進め方のルール
- 構築前に参考画像の比率を数値で測る
- 静止画が承認されるまで動画は作らない

## 過去の失敗（追記していく）
- （Step5で1行ずつ追加）
なぜ必要？ AIは会話が変わると前回の注意点を忘れます。ファイルに書いて毎回読ませることで、「新人に引き継ぎ資料を渡す」のと同じ効果が出ます。

3画像専用のチェックリストを書く

コードを書く前に、10〜12項目の番号付きリストを作ります。

書き方の3ルール

  1. 曖昧な言葉は数値にする
    ✕「肢が細い」 → ○「肢の太さは体長の0.15〜0.25」
  2. ありがちな失敗には「NEVER」を書く
    例：「NEVER 全身を同じ太さの円柱で作らない」
  3. 最後の項目は必ず「暗部密度が参考画像の0.8以上」
1. 体高は体長の 0.18〜0.22 であること
2. 頭部の長さは体長の 0.25〜0.30 であること
3. 肢（ひれ）の太さは付け根の 0.15〜0.25 であること
4. NEVER 緑を面で広く塗らない（先端・縁・リングのみ）
...
12. 暗部密度（luma < 80 の割合）が参考画像の 0.8 以上

※ ピラニアの実例がリポジトリで公開されています。まずはそれを読んで雰囲気をつかむのがおすすめです。

4静止画ループ（Still Loop）

Claudeに次の順で作業させます。

  1. 参考画像と同じポーズで 1600×900 の静止画をレンダリング
  2. 「参考画像」「自分の静止画」「承認済みの静止画」を並べて比較
  3. チェックリスト全項目を yes / partial / no で評価
  4. no → partial の順に修正
  5. ラウンド2で必ず停止し、人間の承認を待つ
描画→比較→採点→修正→人間が承認？

「目視」ではなく「数値」で測る

  • 暗部密度：輝度 luma < 80 のピクセルの割合
  • 体高・頭長・顎/肢の長さ：体長に対する比率
# 暗部密度を測る簡単な例（Python）
from PIL import Image
import numpy as np
img = np.array(Image.open("still.png").convert("L"))
print("暗部密度:", (img < 80).mean())
なぜ数値？ AIも人間も「なんとなく似てる」で妥協しがちです。数値なら、どこが足りないか誰でも分かります。

5修正をジョブディスクリプションに蓄積する

失敗したら、数値付きで1行、JOB_DESCRIPTION.md に追記します。

悪い例良い例
頭が小さかった頭長が体長比0.17で小さすぎた。0.25〜0.30にすること。
暗い部分が少ない暗部密度が0.42で不足。参考画像の0.8倍（0.5以上）を確保すること。
効果 作るたびにルールが賢くなり、次のビルドから同じ失敗をしなくなる。これがこの手法のいちばん大事な仕組みです。

6–8動画・投稿用・レンダリング

Step 6：動画（Film）を作る　※静止画承認後のみ

  • 体型が近い既存作品の振付を1:1で移植し、体だけ差し替える
  • 部品ごとにカメラの位置・角度を変える（同じ位置から撮らない）
  • 約2〜3秒ごとに1部品が分解 → 最後に全体爆発 → 再組み立て → 退出
  • ページには製品名＋部品ごとのボタン＋ライブカードを配置

Step 7：投稿用10秒版

  • 本編の切り抜きではなく、完全に別のスクリプトで作る
  • オープニング・エンディングも毎回変える

Step 8：レンダリング

  • フレーム単位で正確に描画する（画面録画は使わない）
  • 4K相当で撮って1080pにダウンスケール（きれいに見える）
  • 音も同じタイムラインから生成し、−14 LUFSにマスタリング
なぜ画面録画ではダメ？ PCの処理が重いとコマ落ちするため。フレームを1枚ずつ書き出して後で動画にまとめれば、必ず滑らかになります。

❓理解度クイズ

Q1. この手法の核心は？

プロンプトではなく、ジョブディスクリプションと画像専用チェックリストで指示すること。

Q2. 動画を作り始めてよいのはいつ？

静止画を人間が承認した後だけ。

Q3. 「肢が細い」をチェックリストに書くときの直し方は？

数値にする。例：肢の太さは0.15〜0.25（体長比など基準を明記）。

Q4. チェックリストの最後の項目は何？

暗部密度が参考画像の0.8以上。

Q5. 画面録画を使わない理由は？

コマ落ちを防ぐため。フレーム単位で正確にレンダリングする。

Q6. 失敗を次に活かすには？

数値付きで1行、JOB_DESCRIPTION.mdに追記する。
