# Glass-Dome Octopus — STEP 2 3D プロトタイプ

参考画像 1 枚（`assets/reference.png`）から、**Three.js のコードだけ**で組み立てたロボットタコの 3D モデルです。
画像を 3D 空間に貼り付けたものではありません（画像は比較用 UI「参考構図」でのみ表示）。

- 開く：`index.html`（GitHub Pages ではこのフォルダの URL）
- 参考技術：[Nyxera0x/cutaway](https://github.com/Nyxera0x/cutaway)（MIT）— ジオメトリ工房（`sweepX`・`gearGeo` など）、スタジオ照明、JOB_DESCRIPTION / CHECKLIST の方式を流用

> **STEP 2 の範囲で停止しています。** 分解アニメーション・動画・触手の動作制御は未実装です（指示書の禁止事項どおり）。人間の承認後に STEP 3 へ進みます。

## 操作

| 操作 | PC | スマートフォン |
|---|---|---|
| 360° 回転 | ドラッグ | 1 本指ドラッグ |
| ズーム | ホイール | ピンチ |
| 視点リセット | ダブルクリック / 「⟲ リセット」/ `R` | ダブルタップ |
| 自動回転 ON/OFF | 「⟳ 自動回転」/ `Space` | ボタン |
| 部品名 ON/OFF | 「🏷 部品名」/ `L` | ボタン |
| 正面・側面・背面・上 | ボタン | ボタン |
| 参考画像と比較 | 「🖼 参考構図」（参考と同じ構図に移動＋参考画像を表示） | 同左 |

URL パラメーター：`?q=low|high`（画質固定）、`?auto=0`（自動回転なし）、`?labels=0`、`?debug`（FPS 表示）、`?shot=hero|front|side|rear&ui=0`（撮影用）

## 構造（数値）

本体半径 R = 1.0、床 y = 0、カラー（ドームの付け根）高さ 1.45。

| 部品 | 内容 |
|---|---|
| ガラスドーム | 半径 0.965 の半球（赤道より 3.4° 下まで）、MeshPhysicalMaterial transmission=1・ior 1.33 |
| コアリアクター | 発光球 r 0.19 ＋ 暗いリング 3 本＋ワイヤーケージ＋グロー、5 分割の暗いドラム（窓はヒーロー方位） |
| 内部機構 | 縦ギア 6・リム小ギア 12・横の駆動ギア・ピストン 8・ホース 7・上部ユニット・サーボ 12・端子 40・ボルト多数 |
| 下部シェル | 曲面パネル 3 段（10・8・8 枚、窓 7 か所）、暗い内球、内部ギア 10、側面フレア板 2（右に "VT-08"） |
| カメラ | 白いカウル＋ダークベゼル＋緑リング＋黒い光沢レンズ（正面・極角 101°）、副レンズ（方位 50°）、背面ジェットノズル |
| 触手 | 8 本 × 12〜14 節（計 104 節）。付け根直径 0.40 → 先端 0.12。各節：白い 2 枚の装甲・暗いコア・回転リング 2・軸ピン 2・吸着パッド 4（緑リング）・スロット 3・ボルト 4 |
| 小部品 | 約 1,900 個（ボルト・ピン・パッド・スロット・端子など。JOB_DESCRIPTION の目安 260 個を大きく上回る） |

各触手は `T1-root → T1-joint0 → T1-joint1 → …` の親子階層です。関節を回すとその先が全部ついてきます。描画は部品の種類ごとに 1 つの InstancedMesh（8 本分まとめて）で、`tentacles.update()` が関節のワールド行列をインスタンスに写します。STEP 3 の分解・動作はこの関節を動かして実装できます。

## パフォーマンス（正直な報告）

- **フレームレート目標（PC 60fps / スマホ 30fps）は未検証です。** この環境には GPU がなく、ソフトウェア描画（SwiftShader）では 0.4〜7.5 fps でした。これは CPU で描いた値で、実機の性能を表しません。実機で `?debug` を付けて開くと右下に FPS が出ます。
- 描画量：高画質（影＋透過パス込み）約 135 万三角形・約 460 ドローコール／フレーム。低画質（透過なし）約 90 万三角形・約 300 ドローコール。
- 対策：触手の部品は InstancedMesh（種類ごとに 1 つ、8 本分）、ジオメトリとマテリアルを共有、操作していないときは描画を止める（自動回転 OFF 時）、スマホは透過なし・影 1024・画素比 ≤ 1.5。
- 適応画質：最初の 2 秒ごとの計測で 40fps 未満なら画素比を下げ、28fps 未満ならガラスの透過をやめる（ソフトウェア描画のテストでは実際に透過が自動で切れました）。
- リサイズは ResizeObserver で追従、WebGL コンテキスト喪失時はメッセージを表示、ページ離脱時にジオメトリ・マテリアル・テクスチャ・レンダラーを破棄。
