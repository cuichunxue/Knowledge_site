# JOB_DESCRIPTION — Glass-Dome Octopus

毎回のビルド前に読むこと。修正を受けたら「数値付きで1行」ここに追記する。
（ベース：[Nyxera0x/cutaway](https://github.com/Nyxera0x/cutaway) の `docs/JOB_DESCRIPTION.md`、MIT）

```
あなたは参考画像1枚から、Three.js だけでロボット生物を組み立てる 3D エンジニア兼テクニカルアーティストです。

THE LOOK
- 白いシェルはクリアコート＋環境マップ。1枚の滑らかな殻にしない：曲面パネルを隙間つきで分割する
- 緑はアクセントのみ：先端・縁・ベゼル・関節リング・吸着パッドのリング。殻の上に緑の点をばらまかない
- 暗い機構は2層：大きな部品（ギア・リング・アクチュエーター）＋小部品 約260個（ピストン・ホース・ボルト・配線）
- 光る部品（コア・リング）は機構の内側かガラスの奥に置く。表面に貼らない
- 目（カメラ）は黒い光沢レンズ＋細い緑ベゼル
- 腕は1種類だけ（このモデルは触手8本）。1本ごとにポーズと長さを変える。同じ部品の行列にしない
- 白に近いスタジオ背景、床に柔らかい影

THE ORDER
1. 参考画像を先に測る：本体幅に対する比率（ドーム径・高さ、触手の太さ・長さ）と、暗部（luma < 80）の割合
2. 分解する部品はすべて独立したグループ＋名前付きアンカーにする（STEP 3 で開くため）
3. 参考画像と同じ構図で 1600x900 の静止画を撮る
4. 参考画像｜静止画を並べ、900px 幅版も作り、チェックリスト全行を YES / PARTIAL / NO で採点。記憶ではなく画像と比べる
5. 暗部の割合を測る。参考画像の 0.8 未満は NO
6. ラウンド2で止めて人間に見せる。承認まで分解アニメ・動画は作らない

THIS BUILD (STEP 2)
- 参考画像を平面に貼って再現したことにしない（比較用 UI として表示するのは可）
- テストしていない機能・未測定のフレームレートを「達成」と書かない
```

## 修正ログ（1行1件、数値付き）

- R0→R1: 本体が高すぎて（カラー高さ 1.9）触手が「脚」に見えた → カラー高さ 1.45、触手の付け根を極角 118° にして横へ出す。
- R0→R1: 1 本 16〜21 節・サイコロ状の暗い点 → 節数を 1 本ずつ 12〜14 に固定（歩幅を二分探索）、暗いスロットを 1 節 6 個 → 3 個。
- R0→R2: 1 フレーム 360 万三角形（影・透過パス込み）→ R1 で節数削減とスロットの BoxGeometry 化で 162 万 → R2 で触手リングの角丸 3 段 → 1 段にして 135 万。
- R1→R2: 暗部割合が 0.067 と出たが、原因はモデルではなく canvas に重ねた CSS ビネット（中央で白 55%）。スクリーンショットは DOM ごと写る → canvas の上に明るくする重ね表示を置かない。計測は UI を消して撮る。
- R1→R2: 参考構図からコアが見えなかった → ドラム窓とギアの隙間をヒーロー方位（35°）に向ける。
- R1→R2: ガラスが環境の明るい面を一面に映して中が霞んだ → ガラスの envMapIntensity 0.16、roughness 0。
- R1→R2: 手前の触手の先端が床で団子になった → 手前 3 本は床と平行に巻く（tilt ±80〜84°）。

### STEP 3

- 計測：参考画像は 50px の格子を重ねて読み、3D は自分のジオメトリを投影して同じ量を出す（`src/measure.js`）。色の比率は、3D 側はマスクで本体だけを切り抜く。背景のしきい値方式は 3D 側では使わない。
- 改善前→R1: ガラスが半球だけでドーム高さ −21% → ガラスを極角 103° まで、カラーを赤道の 0.2 下へ。参考のガラスは球の上 61% を覆う。
- 改善前→R1: 左右の触手が床にあり 1 本が奥向き（配置 5/8）→ 上 2・横 2（中段）・手前 4、奥向きなし。
- 改善前→R1: カメラのハウジングが +34% → 半径 0.42 → 0.34、前へ突き出す筒。
- R1: 配置を変えたら本体/全幅が +17% になった → 横と持ち上げの触手を 15〜25% 伸ばす。比率は 1 つ直すと別の比率が動くので、毎回全部測り直す。
- R1→R2: 白 1.38 倍・緑 0.70 倍 → 装甲を ±122° に狭め、灰色の下板・継ぎ目・関節の緑ラインを追加（白 1.27 倍・緑 0.86 倍）。
- R2: コアのグローを 2.0 にしたらガラスの外にはみ出した → 1.35。発光のスプライトはガラスの半径を超えない大きさにする。
- R2: 巻きを大きくしたら手前の触手の画面上の長さが +38% → +47% に悪化 → 巻きの半径と届く距離は一緒に調整する（未解決）。
- テスト：ソフトウェア描画は 1fps 前後になる。固定の待ち時間ではなく「条件が満たされるまで待つ」方式でテストする。

### STEP 4（分解・再組み立て）

- 分解は `render(state)` の純関数にする：毎回、保存した初期 Transform から絶対配置を計算する（加算しない）。20 回の往復とランダムなスライダー 100 回で、初期位置との誤差は 0。
- 部品の進捗は「全体スライダーの担当区間」と「個別の進捗」の大きい方。さらに依存関係を足す（コアとギアの前にドーム、下部ギアの前に帯パネル、パッドの前に触手 5）。
- 衝突チェックで見つかった衝突：側面の大きなフレア板（方位 270°）が触手 T2（273°）に向かって開いていた → フレア板は主に上へ（上 0.7・外 0.2）。触手のすぐ横のパネルと下部ギアは、その触手が外れるまで 25〜30% だけ動く。
- 縦ギアは横へ抜くと持ち上がった触手に当たる → ドームが空けた上の空間へ抜く（上 1.15・外 0.3）。リムの小ギアは上 0.5・内側 0.08。
- カメラの光軸がやや下向き（極角 106°）で、真下に触手 T8・T4 がある → 最初の引き出しを「外＋上」にする。
- 円盤状の部品（デッキ・駆動ギア）の外接箱は角が実物より大きく、誤検出を生む → 衝突チェックの結果は候補として扱い、部品名で確認してから直す。
- ダブルタップの判定は 1 か所にまとめる。シングルタップの選択とダブルタップのリセットを別々に判定すると、処理順によって結果が変わる競合になる。
- イベントの時刻は `event.timeStamp` で測る。ハンドラーの中の `performance.now()` は重いフレームで伸びる。さらに、保留タイマーが発火したときに次のタップが進行中なら、その指離れまで判定を待つ。
